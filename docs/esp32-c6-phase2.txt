Phase 2: ESP32-C6, Zigbee and Hue – prepared interfaces
Sources reviewed on 2026-10-29. Not implemented or tested on ESP32-C6.

Phase 1 uses the classic ESP-WROOM-32. It has no integrated 802.15.4 radio for
the future Zigbee design. New hardware is not a prerequisite for current work;
this document is not a purchase recommendation.

Reusable components include the protocol parser, freshness gate, color engine,
mode manager and configuration codec. Wi-Fi, NVS, LED peripherals, pins and
tasks remain platform-specific. A future Zigbee adapter should feed On/Off,
level and static RGB/xy colors into the same main-task ambi_command_t queue.
Zigbee callbacks must not directly access LED drivers or mode state. Manual
OFF/AMBIENT retain priority; AUTO is selected explicitly. Hue should control
one lamp representing the whole strip, while Wi-Fi carries individual zones.

SDK STATUS AND VALIDATION PLAN
- The classic ESP32 prototype builds with ESP-IDF 5.5.6.
- At the review date, Espressif's Zigbee SDK recommends ESP-IDF 5.5.4 and
  recommends Zigbee 2.x for new designs; 1.x is maintained as bug-fix-only LTS.
- Zigbee SDK 2.0.4 release notes name ESP-IDF 5.5.4 as the base. Version 2.0.1
  added ESP-IDF 6.0 support. This does not guarantee every newer IDF version
  or the project's untested Zigbee/IDF 5.5.6 combination.
- Phase 2 therefore needs its own validated, exactly pinned SDK/component
  combination. C6 target/pins/SPI-DMA and manifest constraints must be adapted
  and rebuilt deliberately. The current build targets esp32 only.

RADIO AND DEVICE MODEL
ESP32-C6 provides Wi-Fi and 802.15.4 while sharing a 2.4-GHz radio resource.
Wi-Fi colors and Zigbee must be coordinated. Test join/rejoin during UDP
reception, packet loss, latency, OFF response, channel usage, memory demand and
continued LED output. Do not assume simultaneous full throughput on both radios.

The intended device is Zigbee Color Dimmable Light (0x0102) with On/Off (0x0006),
Level Control (0x0008) and Color Control (0x0300), plus necessary Basic, Identify,
groups and scenes support based on the selected SDK example. Persistent pairing
requires dedicated stack partitions separated from Ambilight configuration.
Do not erase all NVS.

HUE COMPATIBILITY IS UNCONFIRMED
A Zigbee 3.0 device profile alone does not establish Philips Hue Bridge
compatibility. Test actual joining, color/brightness commands, off/on, scenes,
rejoin and restart with pairing retained before claiming successful integration.
Do not change a bridge or Zigbee network without explicit approval.

BOOT STARTUP
Samsung boot-start investigation follows a visible end-to-end Ambilight success.
Manual app launch and a hideable service do not establish boot startup. Review
the specific TV's normal Tizen 4 lifecycle/background rules afterward, without
root or system-file edits. Reliable startup remains an open requirement for
convenient continuous operation; it is neither solved nor declared impossible.
